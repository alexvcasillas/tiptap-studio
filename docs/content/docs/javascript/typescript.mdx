title: TypeScript and errors
description: The types shipped in the package's .d.ts, and how failures reach JavaScript.
---

The package ships a `.d.ts` generated by `wasm-bindgen`. It declares the `TiptapDoc` class
and the module functions, plus hand-written types for the plain objects that cross the
boundary. Every method signature uses those types, so nothing is typed `any`.

## Shipped types

Import them like any other type:

```ts
import type {
  Assoc,
  BlockInline,
  Change,
  DiffGranularity,
  DiffOptions,
  HtmlOptions,
  JSONContent,
  Mark,
  MarkSpec,
  NodeSpec,
  NormalizeOptions,
  Path,
  PosContent,
  PosEdit,
  PosRange,
  Position,
  Range,
  ResolvedPos,
  Schema,
  TextPoint,
  Violation,
  ViolationKind,
} from "@tiptap-studio/rusty-parser";
```

They are declared as follows:

```ts
export type Path = number[];
export interface Mark { type: string; attrs?: Record<string, unknown>; [k: string]: unknown; }
export interface JSONContent {
  type?: string;
  attrs?: Record<string, unknown>;

  text?: string;
  [k: string]: unknown;

export interface Position { child: number; offset: number; }
export interface Range { start: Position; end: Position; }
export type Change =
  | { op: "setAttr"; path: Path; key: string; value: unknown }
  | { op: "removeAttr"; path: Path; key: string }
  | { op: "setText"; path: Path; text: string | null }
  | { op: "spliceText"; path: Path; from: number; lenDel: number; insert: string }
  | { op: "setMarks"; path: Path; marks: Mark[] | null }
  | { op: "setExtra"; path: Path; key: string; value: unknown }
  | { op: "removeExtra"; path: Path; key: string }
  | { op: "insert"; path: Path; index: number; node: JSONContent }
  | { op: "remove"; path: Path; index: number }
  | { op: "replace"; path: Path; node: JSONContent }
  | { op: "move"; path: Path; from: number; to: number };

// ---- schema validation ----
export interface NodeSpec {
  content?: string[] | string;
  group?: string;
  marks?: string[];
  attrs?: string[];
  required_attrs?: string[];

  nodes?: Record<string, NodeSpec>;

  | { type: "insert"; pos: number; content: PosContent }
```

## Method signatures

Parameters and results use the types above. For example:

```ts
export class TiptapDoc {
  private constructor();
  free(): void;
  [Symbol.dispose](): void;
  static fromJSON(value: JSONContent): TiptapDoc;
  toJSON(): JSONContent;
  nodeAt(path: Path): JSONContent | undefined;
  addMark(path: Path, mark_type: string, attrs?: Record<string, unknown> | null): boolean;
  diffWith(other: TiptapDoc, options?: DiffOptions | null): Change[];
  validate(schema: Schema): Violation[];
  // ...
}
export function mapPath(path: Path, changes: Change[]): Path | null;
export function mapPosition(pos: number, edits: PosEdit[], assoc?: Assoc | null): number;
```

Lookups that can miss say so in their result type: `nodeAt`, `firstByType`, `childCount`
and `removeChild` return `undefined` when nothing is there, and `mapPath` returns `null`.
Attribute values are `unknown`, because they can hold any JSON.

### Optional parameters

The trailing `attrs`, `marks`, `options` and `assoc` parameters are optional. Leave them
out, or pass `null` or `undefined`:

```ts
doc.addMark([0, 0], "bold");
doc.insertText([0], { child: 0, offset: 0 }, "Hi ");
mapPosition(10, edits); // same as "left"
```

## Errors

Every method and function that can fail throws a standard JS `Error`. TypeScript does not
declare which ones throw. The `message` carries the Rust error's text:

| Source | Example message |
| --- | --- |
| JSON parsing | `json error: EOF while parsing an object at line 1 column 1` |
| An argument of the wrong shape | ``Error: unknown variant `chars`, expected one of `block`, `inline`, `smart` `` |
| A path-addressed edit on a missing node | `no node at path` |
| Flat positions | `pos: 99 out of range (document size 20)` |
| Inline ranges | `range: offset 99 out of range in child 0` |
| Block structure | `block: no previous sibling to join at [0]` |
| Position edits | `pos-edit: overlapping edit at [2,4)` |
| Change lists | `apply: no node at path [9]` |
| A freed `TiptapDoc` | `null pointer passed to rust` |

Messages are meant for people and logs. Do not parse them: catch the error, and decide what
to do from the call that failed.

```ts
try {
  doc.applyPosEdits(edits);
} catch (err) {
  console.warn("AI edit rejected:", (err as Error).message);
}
```

Methods that look something up do not throw when it is missing. They return `undefined`:
`nodeAt`, `firstByType`, `childCount` and `removeChild`. `mapPath` returns `null` when the
node is gone.
